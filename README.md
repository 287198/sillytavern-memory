# 眠眠机记忆辅助插件

独立使用的 SillyTavern 前端扩展。按楼层总结聊天、整理核心记忆、在角色回复前召回相关经历，并通过普通 JSON 与眠眠机双向交换记忆。无需眠眠机账号或后台服务。

## Git 安装与更新

公开仓库：[287198/sillytavern-memory](https://github.com/287198/sillytavern-memory)。

在酒馆「扩展 → 安装扩展」中填写仓库地址 `https://github.com/287198/sillytavern-memory`，或在酒馆根目录执行（下方以默认用户为例）：

```sh
git clone https://github.com/287198/sillytavern-memory.git data/default-user/extensions/sillytavern-memory
```

以后在酒馆根目录更新：

```sh
git -C data/default-user/extensions/sillytavern-memory pull --ff-only
```

有多个酒馆用户时，把 `default-user` 换成自己的用户句柄。克隆完成后该目录应直接包含 `manifest.json`。更新后刷新酒馆页面；插件记忆保存在浏览器 IndexedDB 中，Git 更新只更新插件文件。

如果之前是直接复制 ZIP 文件夹安装，该文件夹没有 Git 历史：先导出记忆 JSON，将旧文件夹移到备份位置，再用上面的命令克隆到相同路径；不要把克隆命令直接运行在非空旧文件夹里。更新遇到本地修改冲突时先保留自己的修改，不使用强制覆盖命令。

## 首次配置

1. 完成上面的 Git 安装，打开要整理记忆的单角色聊天。
2. 重启或刷新酒馆，点击屏幕右下角「记忆」，或在扩展设置的「眠眠机记忆辅助插件」里点击「打开记忆管理台」。目前面向单角色聊天。
3. 在管理台「API与向量 → 独立总结 API」填写地址、密钥和模型。支持 OpenAI 兼容 Chat Completions 接口，例如 `https://你的服务/v1`。服务须允许酒馆页面跨域请求；插件不使用主聊天 API 的连接、密钥或模型。
4. 密钥默认只保留在当前页面会话。明确勾选「保存密钥到酒馆设置」后才持久保存；记忆 JSON 始终不包含密钥。

「测试连接并获取模型」会在按钮旁显示请求进度、成功或具体错误，最多等待 20 秒。获取成功后用「选择总结模型」下拉选择，自动填入模型字段；不支持 `/models` 的服务仍可手动填写。取得列表只验证模型列表接口，不代表生成接口已经通过测试。

0.3.3 起，点击「测试总结生成」实际调用当前总结模型，检查它是否能返回有效 JSON；测试不读取聊天，不写入记忆。结果和响应诊断就在按钮下方，可在手机查看或复制。总结 API 按配置的请求超时等待。

0.3.4 起移除思考模式开关：模型名称识别为 DeepSeek Flash/V4 Pro 时固定发送 `thinking: {type:"disabled"}`，旧版本保存的思考模式选项不再生效；其他模型不传供应商专用参数。[DeepSeek 官方说明](https://api-docs.deepseek.com/guides/thinking_mode/)中，思考与最终正文分开返回。插件始终只保存最终总结，不使用思考全文。关闭思考偏向速度与输出稳定性，复杂剧情的总结质量仍需结合真实聊天样本评估；生成连接测试只验证有效 JSON，不评价摘要质量。

目录和扩展入口遵循 [SillyTavern 官方扩展文档](https://docs.sillytavern.app/for-contributors/writing-extensions/)。也可在本地开发时放入 `public/scripts/extensions/third-party/`；不要同时安装两份。

manifest 声明最低客户端版本 1.13.5；目前已按官方 release 接口检查并通过模拟酒馆环境的真实浏览器测试，尚未在用户实际酒馆安装环境验收。

## 悬浮管理台

0.3.0 起，扩展面板仅保留当前聊天状态、打开管理台按钮和「显示悬浮入口」开关。详细内容移到独立窗口：

| 页签 | 内容 |
| --- | --- |
| 记忆 | 事件和核心记忆、查看编辑、召回测试、致谢 |
| 总结设置 | 自动总结、注入、楼层阈值、摘要与剧情时间规则 |
| API与向量 | 独立总结连接、模型列表、向量连接与索引 |
| 导入导出 | JSON 交换、来源重算、游标检查 |
| 失败记录 | 失败原因、尝试历史与手动重试 |

顶部补充总结、暂停、核心整理和进度提示始终可见，当前页独立滚动。手机使用近全屏窗口和两行页签，桌面使用较宽窗口并继承酒馆主题。支持 Esc 或关闭按钮；关闭后回到聊天，后台总结与自动索引继续，重新打开保留当前页和输入。禁用插件会关闭窗口并隐藏悬浮入口，重新启用可再次打开。窗口使用原生 dialog 管理焦点，方向键/Home/End 可切换页签。

## 总结与记忆注入

- **日记身份**：当前 char 是写日记的人，最终记忆中的“我”始终指 char，user 是对方。原文或已有摘要即使采用第一/第二/第三人称，也先按姓名、动作与上下文确认人物归属，再转成 char 的第一人称；不能照搬 user 视角，也不编造 char 的感受。总结设置显示双方名称，每批原文与前置上下文都标注来源身份，API system 固定日记视角。此要求同时用于核心整理；模型仍需正确理解来源，旧版已写反的记忆需要手动重算。
- char 一条与 user 一条共两楼，开场白也计一楼；从上下文隐藏的旧 user/char 对话仍按原顺序总结。真正的系统通知、工具记录和其他 swipe 不额外计楼；空工具数组不影响正常回复。
- **记忆页的读取计数**：显示酒馆当前已读取多少条记录、可总结多少楼、包含多少隐藏对话，以及系统/工具/无文本排除数量。插件使用酒馆内存中的原始聊天数组，不依赖屏幕上渲染了多少楼。若已读取数量仍少于聊天列表，请重新打开对应聊天核对；未载入的原文不能凭空总结。
- 0.4.1 修复隐藏旧楼漏计后，旧版本已总结进度可能显示“来源有修改”。先导出备份，再在导入导出确认来源重算；希望全部从原文重做时，选择原文来源、清空当前聊天记忆，再点补充总结。插件不会静默删除旧记忆或混接新旧楼层。
- **补充总结**：从已检查进度下一楼处理到点击时的聊天尾部。300 楼聊天、进度 0、每批 50 楼会从第 1 楼开始。尾部不足阈值也处理；旧失败批次在失败记录中手动补齐。
- **自动总结**：默认关闭。旧楼检查完后，尚未检查的新楼数达到触发阈值才开始；默认阈值 100 楼、每批最多 50 楼。两者独立设置，与手动入口共用队列。角色生成期间不启动总结。已有失败记录不会因自动事件被无限重试。
- **自动补旧聊天**：0.4.0 新增，默认关闭，需同时开启自动总结。关闭时，打开或切换聊天时已有的未检查楼层先手动补齐，之后新楼按阈值自动总结；开启后允许自动处理这段历史。已失败批次仍在失败记录手动重试。关闭自动开关会停止自动任务后续批次，等待当前请求结束，已保存记忆保留。
- **暂停**：等待当前 API 请求结束并丢弃尚未保存的结果，已提交批次保留。刷新后从保存的已检查进度继续。
- **整理核心记忆**：每次处理一批尚未消化的事件，沿用眠眠机五类核心条目规则。已有锁定和手改内容受保护。
- **注入记忆**：默认开启，本地词法召回相关事件、事实和核心条目，不需要向量接口。设置注入深度和字符预算；默认 2200、上限 2800 字符，按完整条目选取。
- **回复历史楼数**与**总结前置上下文楼数**分开配置。当前用户输入额外保留一次；只裁剪本次请求的副本，不删除酒馆聊天文件。前置总结上下文只帮助理解，不重复入库。
- 「测试召回与本次注入」可查看实际选取的文本；每条记忆的「查看与编辑」中可展开来源、事实和时间依据。编辑后内容受保护。

记忆和游标按角色及聊天分别保存到**当前浏览器的 IndexedDB**，不会自动保存到酒馆服务器或同步到其他设备。跨设备使用时先导出 JSON。

## 失败记录与重试

全部楼层按正常规则整理，不因 NSFW 内容预先暂停或跳过。已有摘要优先，没有摘要使用正文。供应商可能拒绝处理内容；插件会记录拒绝原因，不隐式换用主聊天 API。

接口失败、拒绝、输出截断、JSON 错误、来源覆盖不完整时，首次请求后**自动重试两次，共最多三次**。仍失败则保存范围、失败原因、累计尝试次数和原因历史，继续后续批次。打开管理面板的「失败记录与手动重试」，可为单条记录重试；每次手动重试同样最多三次，成功标记已解决，失败保留并累计次数。

面板显示**已总结、待总结、总结失败**楼数。例如 1–50 楼成功、51–100 楼失败、101–300 楼成功：已总结 250/300 楼，待总结 0 楼，总结失败 50 楼。记忆页展开「哪些楼已总结、哪些还没总结」即可查看三类范围；失败区间手动重试，不会重复总结后面已成功的楼层。来源被修改而失效的楼层列入待总结，需要先确认重算。

0.3.3 起，新请求的错误可展开「查看响应诊断（手机可用）」并「复制诊断」。记录 HTTP 状态、响应字段结构、结束原因、正文/思考长度、token 使用和请求设置，不含聊天提示词、生成正文、思考全文或密钥；诊断不随记忆 JSON 导出。剪贴板不可用时显示文本供长按复制。旧失败历史没有响应结构，更新后手动重试即可生成新诊断。输出 `length` 或只有思考时可增加输出上限、减少每批楼数或更换总结模型；HTTP 200 中的服务端错误会显示具体原因。

状态栏同时显示已存事件/核心数量与待重试批次。已成功的楼层照常计入已总结，前面的失败不会将完成数显示为零。打开「失败记录」查看原因并手动重试；「补充总结」处理尚未尝试的新楼层，旧失败区间不会被反复自动重试。

总结和自动索引使用酒馆实时生成状态；提示词预览不会占用生成锁，角色停止或结束回复后恢复处理。如果旧版本一直提示「角色仍在回复」，更新插件并刷新酒馆页面后再重试。

### 旧聊天、多个预设混用时从原文精炼

在「管理台 → 总结设置 → 总结来源」选择「仅从聊天原文精炼（旧聊天/混用预设）」。选择按当前聊天保存，其他聊天保持各自选择。

切换来源不重写已经成功的记忆。只重做部分楼层可在导入导出指定范围；全部从原文重做时，先选择原文来源，按下文清空当前聊天记忆，再点击补充总结。

原文模式直接读取每楼保存的完整正文，跳过摘要和时间正则/JSON 字段，由独立总结 API 精炼成原有记忆格式。预设、排版模板和正文里的输出指令作为来源数据处理，不能当成已经发生的剧情；日期只使用正文证据或手动锚点。前置上下文保留预算内最近的完整楼层；单楼超过容量时明确报错，可提高「总结输入字符容量」。

0.4.3 起由模型按语义、上下文和剧情连续性判别主线，不需要为每种旧预设填写标签：

- 主线实际经历写入 char 第一人称日记。混合楼层保留主线部分，排除附加内容。
- 摘要、大总结用于核对主线事实；可以利用其中可核验的主线信息、合并重复，但不会把“生成摘要／报告”本身记成角色经历。
- 明确非正史的小剧场、平行设想、场外写作要求和附加输出不入记忆。真实剧情中的写报告、表演、做梦行为仍可保留；梦中虚构情节不能当作现实。不能只凭关键词删除。
- 整楼没有可利用主线事实时，模型必须返回来源 ID、分类和具体理由；未知、重复或同时用于记忆的忽略 ID 会触发校验失败与正常重试。管理台「总结设置 → 正文判别与忽略记录」可在手机查看忽略楼层和原因。检查后没有生成事件的楼层也计入已总结，不会反复重试。
- 原始来源保留在当前浏览器用于核对；事件、原子事实、召回和核心整理使用模型判别后的主线文本。导出所需来源活动同样使用主线文本，忽略记录不进入导出列表，避免导入其他系统后附加内容重新被召回。普通 JSON 格式不变。

这些规则指导模型判断，结构校验不能证明模型对所有未知预设都判断正确。旧版错误记忆不会自动删除或改写；要清除其影响，先导出备份，再按原文来源重算范围或清空当前聊天记忆后重做。摘要优先模式仍可用，但读取已提取摘要时无法恢复被摘要省略的正文，旧预设混用建议选择原文模式。

还没检查过的楼层点击「补充总结」，已有失败到「失败记录」手动重试。已经成功但想按原文重新精炼的旧范围，在「导入导出」填写起止楼层并点击「重算指定楼层范围」。测试提取按钮会显示「直接使用聊天原文」，便于先确认来源。

核心整理和范围重算也使用相同重试与失败记录入口。范围重算失败只记录原因，原记忆与进度不改变，重试全部成功后统一提交。暂停或来源改变会取消任务；来源失效记录需重新选择来源整理。重置进度后，受影响的旧失败记录标记来源失效并保留历史。

来源校验能够发现**漏楼、缺少来源 ID、非法引用或输出格式错误**，无法可靠判断 AI 是否遗漏了某楼里的具体剧情细节。失败原因隐藏配置中的密钥；失败记录留在当前浏览器，不随记忆 JSON 导入导出。API 地址或模型尚未配置时直接提示配置，不批量生成失败记录。

## 勾选导出与清空重做

在「管理台 → 导入导出」点击「导出记忆 JSON」，先显示当前记忆的快照列表。默认全选，可取消不要的事件或核心整组，也可点全不选后逐条勾选；未合并的活动单列。点击「导出已选记忆」下载普通 JSON，只包含所选记忆记录及它们所需来源活动。没有选择时禁止下载。打开列表后新生成的记忆不自动进入这份快照，重新点击导出可刷新列表；切换聊天会取消旧列表。

全部重新精炼：

1. 可先全选导出作备份。
2. 在「总结设置 → 总结来源」选择「仅从聊天原文精炼」。
3. 到「导入导出」点击「清空当前聊天记忆」并确认。当前聊天的事件、核心（含手动修改和锁定条目）、来源活动、失败记录与进度将清空；聊天原文、其他聊天、API 配置和当前来源选择保留。
4. 点击顶部「补充总结」，从第 1 楼重新精炼。清空后自动总结会暂停，刷新也不会自动启动；手动补充或明确重新开启自动总结可恢复自动调度。

清空需要当前记忆任务空闲；如正在运行，先暂停并等当前请求结束。关闭管理台只是隐藏窗口，之前手动启动的任务会继续。翻页只切换列表，不调用总结 API，也不覆盖总结进度提示。

## 预设摘要与时间

在管理台「总结设置 → 摘要与剧情时间提取」配置。摘要提取先尝试 JSON 字段路径，再尝试正则第一个捕获组，未命中才使用整楼正文。示例：

新配置默认开启「自动识别当前摘要格式」和「自动识别剧情时间格式」：只读检查当前允许启用的全局/角色/预设正则、当前预设的输出标签，以及最近 40 条角色存储消息。单一格式有实际命中时自动填入提取字段，并显示来源和预览；多个格式时从对应下拉列表选择。预设只有格式约定、历史尚无命中时展示候选，不把它当成已存在摘要。普通 `<summary>` 折叠栏标题、思维链和状态栏不会作为可靠摘要；明确标为剧情摘要的 `<details>` 支持提取标题后的正文。

0.2.1 修复识别保存触发设置更新后的循环：内容不变时不反复保存，不重建下拉选项。支持正文/标签/代码块里的 JSON 摘要与日期字段，例如 `memory.summary` 和 `status.date`。自动填入正则或 JSON 路径中的一种，另一个留空是正常的。时间需要有实际剧情日期或明确相对日期，仅有 `14:30`、空模板、现实发送时间或多个冲突日期不能自动推断年月日。

切换聊天、预设、角色生成完成或点击识别按钮时重新检查。手动编辑提取规则会关闭自动识别并保留配置；升级前已有手动规则同样保留。自动识别不运行正则替换、不改预设或聊天，也不能恢复已删除的原文。复杂宏、非标准标签或无法确认的格式可继续手动设置。

```text
摘要正则：<memory_summary>([\s\S]*?)</memory_summary>
摘要 JSON 字段路径：memory.summary
时间正则：<time>(.*?)</time>
时间 JSON 字段路径：state.date
```

可指定「测试提取楼层」，预览命中摘要或回退正文，以及该楼的时间。插件读取当前 swipe 的存储消息；仅隐藏显示的摘要仍可提取。已被替换并从存储中删除的内容无法恢复，参见 [官方 Regex 说明](https://docs.sillytavern.app/extensions/regex/)。摘要只代表自身来源楼层，不能自动替代前面几十楼。

默认使用**剧情时间**。时间来自指定字段、时间标签或明确正文日期；手动配置「某楼对应剧情日期」可建立锚点。支持 `YYYY-MM-DD`、中文年月日、可选时分、UTC 偏移，以及锚点后的「次日／第二天／翌日／三天后」等明确承接。没有年份、虚构历法、多日期冲突或不明确的计划/回忆保留未知，不能由补总结当天的日期补猜。

现实发送时间与本次生成时间独立保存。只有勾选「使用现实发送时间作为发生时间」才将有效 `send_date` 当作发生时间。无法解析的来源时间仍保留未知。

## 修改来源和指定范围重算

已总结楼层被编辑、删除、插入或切换 swipe 后，面板显示最早失效楼层，总结停止。点击「确认从失效楼重算」，再点击补充总结；旧记录保留，受影响且未经手改的旧事件和核心条目暂停召回。

「游标归零检查全史」保留已有记录，从第 1 楼重新检查。同一来源已有记录会复用，不直接清空记忆。

填写起止楼层并点击「重算指定楼层范围」可重算历史局部。为保持事件完整，范围与已保存事件重叠时会扩大到该事件的全部来源楼层，确认框显示实际范围。全部请求成功后统一保存；中途暂停、失败或来源改变不提交重算。其他未总结楼层仍保留在待处理范围。

## 与眠眠机双向交换

酒馆：打开当前角色聊天 → 记忆管理台 →「导入导出」→ 导出记忆 JSON；导入时先查看新增、重复、冲突和核心候选，再确认追加。

眠眠机：进入对应角色的**角色记忆库 → 导入导出**，导出或选择同格式 JSON。导出包括近期活动、时期记忆、核心条目和旧“大块记忆”。历史大块记忆完整保存为一条标记时间未知的时期记忆，原文日期仍保留在正文中。

导入映射到当前选定角色；同名不会自动合并。相同来源去重，同来源不同内容保留本地版本并统计冲突；核心以候选条目追加，保留已有锁定和手改内容。来源引用重新映射，原应用、聊天、楼层及内容指纹保留。JSON 导入**不改变酒馆总结游标**。

文件是 UTF-8 普通 `.json`，公开契约见 [JSON-FORMAT.md](JSON-FORMAT.md)、[JSON Schema](conversation-memory.schema.json) 和 [可导入示例](example-memory.json)。这不是完整聊天备份，也不包含 API 配置、向量缓存或内部数据库 key。

当前实现双向文件交换和可选向量增强召回。后续 CDN 转发、一键聊天记录同步、云端传输和群聊暂未接入。

## 向量模型与语义召回

打开管理台「API与向量 → 向量模型与语义召回」，配置独立的 API 地址、密钥和 embedding 模型：

1. 点击「获取向量模型列表」，从下拉列表选择，或手动填写服务支持的 embedding 模型。列表可能包含普通聊天模型，不能凭列表名字保证向量能力。
2. 点击「测试向量接口」，验证 `/embeddings` 能返回有效向量并显示维度。
3. 勾选「启用向量增强召回」，会自动补建当前聊天已有记忆的索引；切换聊天或更换接口/模型后也自动检查。
4. 总结、重算、导入、编辑或核心整理保存后自动补建，仅处理新增或变化的内容，未改变的索引复用。可随时点击「建立/更新向量索引」手动检查或重试。如果服务在同一模型名称下更换了向量维度，可点「重建全部向量」强制更新。

自动索引等待当前总结/核心整理及角色生成完成后处理，不阻塞记忆保存。连续改动会合并处理；处理中改动来源、切聊天、禁用插件或点击暂停时丢弃过时结果。接口失败显示原因并保留本地召回，不无限循环请求；下一次记忆更新或手动更新可以重试。

向量功能默认关闭。开启后，沿用眠眠机的召回排序规则，只在事件/核心的词法命中不足时使用向量补充，不直接取代核心与来源保护规则。索引包含当前聊天的有效事件和核心；每条向量输入最多取 6000 字符，每次最多 16 条，不截断保存的记忆。接口会收到选取的记忆文本和本次检索主题。主聊天仍使用酒馆原有连接，向量接口不隐式复用总结或主聊天密钥。

向量缓存独立保存在当前浏览器 IndexedDB，按当前聊天、接口、模型及来源内容区分；旧内容索引不参与修改后记忆的检索。无索引、接口失败或维度变化时继续词法召回，并在向量面板说明原因。实时查询最多等待 12 秒；索引操作沿用所配超时。缓存与密钥不随 JSON 导出，跨设备导入后启用向量功能会自动补建。未勾选保存向量密钥时，刷新页面后需重新填写。

## 开发与验证

以下开发检查在眠眠机源码仓库根目录执行，安装插件无需运行构建或安装 Node 依赖：

```text
node scripts/build-sillytavern-memory-plugin.js
node scripts/build-sillytavern-memory-plugin.js --check
node --test scripts/memory-transfer.test.js scripts/memory-sillytavern-engine.test.js scripts/memory-sillytavern-api.test.js scripts/memory-sillytavern-adapter.test.js scripts/memory-sillytavern-vector.test.js
node scripts/memory-sillytavern-browser.test.js
node scripts/memory-sillytavern-console.test.js
```

`shared.js` 由眠眠机的 model、journal、digestion、recall、transfer 五个源模块生成，并隔离在自己的运行域。修改规则应编辑原模块后重新构建，避免两端提示词和校验漂移。插件运行时无需访问眠眠机网站。
