# 眠眠机记忆辅助插件

独立的 SillyTavern 前端扩展：以 char 第一人称整理记忆，在回复前召回相关经历，通过普通 JSON 与眠眠机交换记忆。无需眠眠机账号。

## 安装和更新

在酒馆「扩展 → 安装扩展」填写公开仓库地址：https://github.com/287198/sillytavern-memory 。也可以在酒馆根目录执行：

```sh
git clone https://github.com/287198/sillytavern-memory.git data/default-user/extensions/sillytavern-memory
```

更新：

```sh
git -C data/default-user/extensions/sillytavern-memory pull --ff-only
```

多用户安装请将 `default-user` 换成自己的用户句柄。更新后刷新酒馆。记忆保存在当前浏览器 IndexedDB，Git 更新不清空记忆；换设备请先导出 JSON。ZIP 安装目录没有 Git 历史，应先备份，再克隆安装；本地修改冲突时保留修改，不强制覆盖。

## 开始使用

1. 打开单角色聊天，点击右下角「记忆」，或扩展设置中的「打开记忆管理台」。
2. 在「API与向量」填写独立总结 API 地址、密钥和模型。支持 OpenAI 兼容 Chat Completions，例如 `https://你的服务/v1`。不使用酒馆主聊天的连接或密钥。
3. 点击「测试连接并获取模型」，从列表选择；平台不支持模型列表时可手填。再点击「测试总结生成」验证生成接口。
4. 点「补充旧聊天」整理已有对话，或在「总结设置」开启自动总结。默认开启记忆注入，本地召回无需向量模型。

密钥默认仅在本次页面中使用。勾选保存后才进入酒馆设置，JSON 始终不包含密钥。API 服务须允许酒馆页面跨域访问。DeepSeek Flash/V4 Pro 固定关闭思考，只读取最终正文；没有思考开关。

## 两种总结方式

- **自动跟随当前摘要**：读取当前启用正则、预设和最新回复中的摘要格式，自动提炼并供角色回复时召回。默认关闭；可设置每隔多少楼触发。摘要缺失时回退正文。
- **手动补充旧聊天**：顶部「补充旧聊天」直接读取完整原文，适合玩了很多楼、混用不同预设的历史，不需要选择来源或填写正则。从未处理的下一楼分批继续，尾部不足阈值也处理；旧失败区间在「失败记录」手动重试。

char 和 user 各一条算一楼。隐藏旧对话仍计入，真正系统通知、工具记录和其他 swipe 不重复计楼。总结以 char 为“我”，按语义判别主线，利用摘要核对事实，排除场外指令和明确非正史小剧场。模型判断仍可能有误，旧错误记忆可编辑、局部重算或清空重做。

打开聊天不会默认自动补旧历史。主界面简短显示记忆数量与进度；「记忆 → 查看总结进度」可查看哪些楼成功、失败或待处理。摘要规则、字段路径、剧情日期锚点、容量、每批楼数和注入参数都在折叠的高级设置里。默认总结输入 120000 字符，自动减小批次、不截断原文；2800 字符仅是回复注入上限。输出 token 上限位于「API与向量 → 独立总结 API → 请求高级设置」。

## 一键补全剧情时间

「记忆」页点击 **一键补全时间**，沿用总结 API，结合全部事件摘要、原有顺序、已知剧情日期和“今天、昨天、明天、几天前/后、上午、下午”等来源线索补全未知事件时间。只改时间和时间标题，不重写事件、不覆盖已有日期。补出的时间标记“推测”，依据默认折叠；线索不足仍保留未知。API 请求不携带现实发送/获知时间作为日期依据。

预设没有日期时，展开 **故事大致时间线（可选）**，例如：

```text
2024年秋天认识，冬天确定关系，2025年3月开始同居。
2025-04-01一起回家，第二天去了医院。
```

时间线按当前聊天保存；清空记忆仍保留这份背景。只给到年、月或季节时，补出的事件保留大致时间范围，不擅自缩成某一天。没有具体时刻也不编造分钟。没有明确关联的事件仍保持未知。

建议在转到眠眠机前先补时间，再导出 JSON。文件携带剧情时间、范围、“推测”标记与依据；未知日期仍为零，兼容索引 `at` 根据相邻事件及来源顺序保留列表位置，不能当成真实剧情日期。跨日回忆、倒叙和事件归属仍需要模型正确理解，用户可先检查结果。

## 导出、导入和重做

在「导入导出」点击导出，列表默认全选，取消不要的条目，再点「导出已选记忆」。文件包含所选事件、核心和必要来源，不包含配置、失败记录或向量缓存。选取列表是快照，新记忆需重新打开导出列表。

眠眠机的对应入口为角色记忆库的「导入导出」。导入前显示新增、重复和冲突；相同来源去重，同来源不同内容保留本地内容，核心候选追加，锁定和手改内容保留。JSON 导入不改变酒馆总结进度。契约见 [JSON-FORMAT.md](JSON-FORMAT.md)、[Schema](conversation-memory.schema.json) 和 [示例](example-memory.json)。

全部重做：先导出备份，在「导入导出」清空当前聊天记忆并确认，再点顶部「补充旧聊天」。清空包含手动修改、核心和失败记录，原文、其他聊天、API 设置与故事时间线保留；自动总结暂停，不会立刻调用 API。局部重算在「导入导出 → 高级重算」，先确认实际影响范围，成功后统一保存。

## 失败和暂停

首次失败自动重试两次，共三次。仍失败则保留原因并继续其他批次，在「失败记录」手动重试。手机可展开、复制响应诊断；不需要浏览器控制台。记录不包含提示词、正文、思考全文或密钥，不随 JSON 导出。补时间的失败也走同一入口；缺乏时间线索属于正常未知，不无限重试。

总结不因 NSFW 内容默认暂停；供应商拒绝时按普通失败记录原因。来源覆盖检查可以发现漏楼或非法引用，不能保证模型没漏掉楼内剧情。

「暂停」等待当前请求结束并丢弃未保存结果，已完成批次保留。关闭管理台只隐藏窗口，任务继续；换聊天、修改来源或禁用插件取消过时结果。管理台支持 Esc、焦点约束和键盘切换页签，手机接近全屏并继承酒馆主题。

## 向量模型（可选）

「API与向量 → 向量模型与语义召回」配置独立的 embeddings 地址、密钥和模型，测试后开启。现有记忆自动补建索引，总结、导入、编辑、补时间和核心整理保存后自动更新，未变内容复用。失败保留本地召回，可手动更新或重建。向量接口会收到记忆文本和检索问题；缓存按聊天、接口、模型和来源内容隔离，不随 JSON 导出。
